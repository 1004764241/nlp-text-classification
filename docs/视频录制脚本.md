# 课程报告视频录制脚本

> **题目**：基于 TF-IDF 与支持向量机的中文商品评论多分类研究  
> **建议时长**：8 ~ 12 分钟  
> **录制建议**：PyCharm 或 VS Code，字体放大到 16px 以上，终端拉到屏幕下方 1/3

---

## 一、开场白（约 30 秒）

> 打开 IDE，让项目目录树显示在左侧，先不开任何文件。

**介绍语：**

"大家好，我是 XX，今天给大家演示我的自然语言处理课程大作业——基于 TF-IDF 与支持向量机的中文商品评论多分类研究。

这个项目的目标，是对来自京东、淘宝等平台的真实用户评论，自动判断它属于哪一类商品，一共覆盖书籍、手机、平板、水果、洗发水等十个类别，总计约六万两千条评论。

整个项目分四个步骤：数据预处理、TF-IDF 特征提取、模型训练，以及最终的评估与可视化。接下来我按顺序演示。"

---

## 二、项目结构介绍（约 1 分钟）

> 在 IDE 左侧目录树展开项目，鼠标依次点 code / configs / data / results / models 目录。

**介绍语：**

"先看一下项目结构。

`code/` 目录下是四个核心脚本：`preprocess.py` 负责数据清洗和分词，`train.py` 负责训练模型，`evaluate.py` 负责在测试集上跑评估指标并生成图表，`predict.py` 可以对单条文本进行实时预测。

`configs/default.yaml` 是统一配置文件，所有超参数——比如词表大小、n-gram 范围、模型类型——都在这里集中管理，脚本不需要改代码就能切换实验设置。

`data/processed/` 保存预处理后的三个 CSV 文件，`models/` 保存训练好的模型，`results/` 保存实验指标和图表。"

---

## 三、配置文件（约 1 分钟）

> 打开 `configs/default.yaml`，把整个文件显示出来。

**运行命令**：无需运行，直接展示文件内容。

**介绍语：**

"打开配置文件。可以看到，我把所有关键参数集中在这里。

`train.model_type` 这一行最关键——写 `tfidf_svm` 就用支持向量机，改成 `tfidf_nb` 就换成朴素贝叶斯，`tfidf_lr` 就是逻辑回归，一行搞定模型切换。

`max_features: 50000` 是 TF-IDF 词表大小，`ngram_range: [1, 2]` 表示同时使用单词和相邻两词的组合——也就是 Bigram，这能捕捉"非常满意""质量很差"这类短语的整体语义。

`preprocess` 节设置了验证集和测试集各占 10%，加上停用词文件路径。整个实验的超参数一目了然，也方便复现。"

---

## 四、数据预处理（约 2 分钟）

> 打开 `code/preprocess.py`，先展示 `tokenize()` 函数和 `clean_dataframe()` 函数，再切到终端运行。

**介绍语（看代码时）：**

"打开预处理脚本。核心是这两个函数。

`clean_dataframe()` 做了三件事：删掉空值行、去掉重复评论、过滤掉长度不足五个字的极短文本，原始六万两千七百七十四条，最后留下六万两千六百零五条有效数据。

然后是 `tokenize()` 函数——它调用 jieba 的精确模式对每条评论分词，同时过滤停用词和纯标点，把「这款手机信号很差」这样的句子切成「这款 手机 信号 很 差」这样空格分隔的词元字符串，交给后续的 TF-IDF 向量化器处理。

下面在终端跑一下。"

**运行命令：**

```bash
cd ~/自然语言处理大作业
source .venv/bin/activate
python code/preprocess.py --config configs/default.yaml
```

> 等待运行，**边等边介绍输出内容**：

**介绍语（看终端输出时）：**

"可以看到，程序先打印配置信息，然后依次完成四步：数据清洗、加载停用词、jieba 分词——这一步最慢，大概三到五分钟，因为要对六万条评论逐条分词——最后是数据集划分。

程序用了分层抽样，保证书籍、热水器这类数量少的类别在训练集、验证集、测试集里比例一致，避免随机划分导致某类样本全跑到训练集里去。

完成后，`data/processed/` 下会生成 train.csv、val.csv、test.csv 三个文件，每条数据有原始文本、分词结果、类别标签三列。"

---

## 五、模型训练（约 2 分钟）

> 打开 `code/train.py`，先展示 `build_pipeline()` 函数，再切到终端运行。

**介绍语（看代码时）：**

"打开训练脚本，核心是 `build_pipeline()` 这个函数。

它把 TF-IDF 向量化器和分类器封装成一个 sklearn Pipeline，这样训练和推理时只需要调用 pipeline.fit 和 pipeline.predict，不用手动管理向量化和模型的衔接。

TF-IDF 这里用了两个关键参数：`sublinear_tf=True` 启用对数平滑，防止某个词出现一百次就把权重放大一百倍；`token_pattern=r'\\S+'` 用空格切分，因为输入已经是 jieba 分词过的结果了，不需要再做分词。

下面跑训练。"

**运行命令：**

```bash
python code/train.py --config configs/default.yaml
```

> 等待约 10 秒，**边等边介绍**：

**介绍语（看终端输出时）：**

"因为 TF-IDF 生成的是高维稀疏矩阵，LinearSVC 对这种特征非常友好，所以整个训练过程很快，纯 CPU 大概七到八秒就完成了。

可以看到训练完成后，程序直接在验证集上跑了一次评估，打印出每个类别的 Precision、Recall 和 F1-score。验证集准确率大概在百分之八十八到八十九左右。

训练好的模型序列化成了 `tfidf_svm_model.pkl`，保存在 `models/` 目录下，下一步评估直接加载这个文件。"

---

## 六、模型评估与可视化（约 2 分钟）

> 打开 `code/evaluate.py`，简单展示评估指标和绘图部分，再切到终端运行。

**介绍语（看代码时）：**

"评估脚本会在测试集上预测，然后输出三个结果：完整的分类报告 JSON 文件、混淆矩阵热力图，还有各类别 Precision/Recall/F1 的柱状图。

绘图用了 matplotlib 和 seaborn，脚本里做了中文字体的自动检测，在 macOS、Linux、Windows 上都能正常显示中文标签。"

**运行命令：**

```bash
python code/evaluate.py --config configs/default.yaml
```

> 运行完成后，**打开生成的图片**（results 或 figures 目录）：

**介绍语（展示结果时）：**

"来看结果。

整体准确率达到了 89.23%，宏平均 F1 为 88.11%。

从各类别指标来看，蒙牛 F1 值达到了 1.00，几乎完美识别——因为「牛奶」「蒙牛」这些词非常有辨识度，TF-IDF 能精准捕捉。酒店和书籍 F1 也都超过了 0.95，同样是因为这两类有大量专属词汇。

有一个明显的弱项是热水器，Recall 只有 0.44。原因很直接：热水器的训练样本只有四百多条，占总量不到 1%，严重的类别不均衡让模型没有充分学习到它的特征。这也是后续改进的一个主要方向——可以用上采样或者代价敏感学习来缓解。

看混淆矩阵可以更直观地看到，平板、手机、计算机这三类数码产品之间有一定的误分——它们的评论里都会出现「屏幕」「性能」「系统」这类词，TF-IDF 的词袋模型无法区分语义，这也是传统方法的固有局限。"

---

## 七、单条预测演示（约 1 分钟）

> 切到终端，演示 predict.py。

**运行命令（建议依次执行这几条，效果更直观）：**

```bash
# 示例 1：手机评论
python code/predict.py --text "这款手机信号很差，用了一个月就卡死，非常失望"

# 示例 2：食品评论
python code/predict.py --text "蒙牛纯牛奶味道很好，孩子很喜欢喝，会继续购买"

# 示例 3：酒店评论
python code/predict.py --text "房间很干净，前台服务热情，入住体验很好，下次还会来"
```

**介绍语：**

"最后演示一下实时预测。输入一条关于手机的差评，可以看到模型直接输出预测类别「手机」。

再输入一条关于蒙牛的评论——直接命中「蒙牛」。

最后是酒店评论，「前台」「入住」「房间」这些词让模型很有把握地判断为「酒店」。

整个预测是毫秒级的，因为模型文件已经加载好了，只需要做一次 TF-IDF 变换和 SVM 分类即可。"

---

## 八、结尾（约 30 秒）

> 回到 IDE 目录树，做一个整体扫视。

**介绍语：**

"好的，以上就是这个项目的完整演示。

总结一下：我们用 jieba 分词 + TF-IDF + LinearSVC 的组合，在十类中文商品评论分类任务上，实现了 89.23% 的准确率和 88.11% 的宏平均 F1，整个训练流程在普通 CPU 上七八秒就能完成。

主要的局限在于：热水器类别样本不足导致召回率偏低，以及词袋模型无法区分语义相近的数码类别。后续可以考虑引入预训练词向量或 BERT 来进一步提升效果。

感谢大家观看，如有问题欢迎交流，谢谢！"

## 附：常见临场问题处理

| 情况 | 处理方式 |
|------|---------|
| jieba 分词卡很久 | 正常现象，六万条评论约 3~5 分钟，可以边等边讲解原理 |
| 找不到数据文件报错 | 确认 `data/online_shopping_10_cats.csv` 存在 |
| 图片中文显示方框 | evaluate.py 已做字体自适应，macOS 下正常 |
| 想跳过分词直接演示训练 | 确保 `data/processed/` 下三个 CSV 已存在即可 |
